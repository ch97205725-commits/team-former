# PRD: 팀 프로젝트 팀 편성 웹 앱 (Team Former)

## 1. 배경과 목표
팀 프로젝트 수업에서 학생이 스스로 팀을 꾸리되, 팀마다 역할이 고르게 섞이도록 규칙을 지키게 한다.
모집이 끝난 뒤 팀에 들어가지 못한 학생은 AI가 배정안을 내고, 앱이 그 답을 규칙으로 검사한 뒤 관리자가 확정한다.

- 목표 1: 학생이 지원·투표만으로 팀을 만든다(규칙을 어기는 지원은 앱이 막는다).
- 목표 2: 마감 뒤 남은 학생을 규칙에 맞게 빠짐없이 배정한다.
- 목표 3: AI가 늦거나 틀려도 배정이 끝까지 완료된다.

## 2. 사용자
| 사용자 | 하는 일 |
|---|---|
| 학생(가상 명단의 학생) | 학번·비밀번호(1234)로 로그인, 팀 목록·팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성·거부 |
| 관리자(교수, 학번 `admin`) | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

## 3. 핵심 규칙
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개(명단에 정해짐).
- 확정한 팀은 모두 2~4명, 팀 안에 주 역할 중복 없음.
- 모든 팀에 기획자와 웹 프로그래머를 서로 다른 학생이 맡음(주 역할이나 보조 역할로).
- 지원: 빈 팀은 바로 승인. 팀원이 있으면 그때의 팀원 모두가 찬성해야 승인, 한 명이라도 거부하면 바로 거절. 투표는 바꿀 수 없음.
- 막힘: 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 모집 마감, 필수 포함 역할을 맡을 학생의 자리가 모자람.
- 승인 직전에 규칙을 다시 검사한다(같은 팀에 대기 지원이 여럿일 때 앞의 지원이 먼저 승인될 수 있으므로).
- 마감: 대기 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠짐.

## 4. 기능 요구사항
| 번호 | 기능 | 완료 기준 |
|---|---|---|
| F1 | 로그인 | 학번·비밀번호가 맞을 때만 로그인. 비밀번호는 bcrypt 해시로 저장 |
| F2 | 관리자 계정 | 앱 시작 때 `ADMIN_PASSWORD`로 만들거나 갱신. 명단을 다시 올려도 남음 |
| F3 | 명단 올리기 | BOM이 붙은 UTF-8 CSV와 팀 수로 상태 초기화 |
| F4 | 팀 목록 | 팀원 이름, 주 역할, 보조 역할, 내 팀 표시, 아직 팀이 없음 표시 |
| F5 | 지원 | 위 규칙에 따라 승인/대기/막힘 |
| F6 | 투표 | 찬성·거부, 이미 투표했으면 "내 투표: 찬성" 표시 |
| F7 | 다른 사람의 변경 보기 | `st.fragment`로 3초마다 바뀐 부분만 다시 그림 |
| F8 | 모집 마감 | 대기 지원 거절, 1명 팀 해체, 팀이 없는 학생 표시 |
| F9 | AI 배정 | 오픈라우터 1·2·3차 모델, 모델마다 전체 120초 제한, 몇 차 모델을 기다리는지 표시 |
| F10 | 배정안 검사 | 다섯 가지 검사(빠짐없음, 한 팀만, 2~4명, 주 역할 중복 없음, 필수 역할) |
| F11 | 앱이 스스로 배정 | 3차까지 실패하면 모든 경우를 따져 규칙을 지키는 배정을 찾음 |
| F12 | 배정 불가 안내 | 규칙을 지키는 배정이 없으면 AI를 부르지 않고 이유를 보여 줌 |
| F13 | 확정 | 검사를 통과한 배정안만 DB에 저장 |
| F14 | DB 일시정지 막기 | 깃허브 액션이 매일 DB에 질의 |

## 5. 화면 key (자동 채점용)
공고 2.7절 표의 key를 그대로 쓴다: `login_student_no`, `login_password`, `login_submit`, `whoami`, `result`,
`team_{n}`, `apply_{n}`, `vote_yes_{학번}`, `vote_no_{학번}`, `admin_roster_file`, `admin_team_count`,
`admin_start`, `admin_close`, `unassigned`, `admin_assign`, `assign_status`, `admin_confirm`.
결과 안내는 "승인", "대기", "거절", "막힘" 가운데 하나로 시작한다.

## 6. 비기능 요구사항
- 보안: 키·DB 주소·관리자 비밀번호는 `.env`/Streamlit Secrets에만. 화면·로그에 출력하지 않음. 학생 계정은 관리자 기능을 쓸 수 없음.
- 성능: DB 연결 풀을 한 번만 만들어 재사용.
- 동시성: 쓰기 작업은 트랜잭션 + advisory lock으로 하나씩 처리, DB 유일성 제약으로 같은 자리 중복을 막음.
- 배포: Streamlit Community Cloud, DB는 Supabase(테이블 이름 `tf_` 접두사).

## 7. 범위 밖
