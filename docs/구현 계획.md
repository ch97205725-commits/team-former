# 구현 계획

## 1. 파일 구성
| 파일 | 하는 일 |
|---|---|
| `streamlit_app.py` | 화면(로그인, 학생 화면, 관리자 화면). 공고 2.7절의 key를 모두 지정 |
| `service.py` | 지원·투표·마감·명단 초기화·확정. 한 함수가 한 트랜잭션 |
| `rules.py` | 팀 규칙, 필수 포함 역할 자리 계산, 배정안 다섯 가지 검사, 모든 경우를 따지는 배정 탐색 |
| `ai.py` | 오픈라우터 호출(모델마다 전체 120초 제한), 프롬프트, 답 읽기 |
| `db.py` | 연결 풀(한 번만 만들어 재사용), 트랜잭션 실행, 스키마 적용 |
| `schema.sql` | `tf_` 테이블과 제약. 앱이 시작할 때 실행 |
| `scripts/keepalive.py`, `.github/workflows/db-keepalive.yml` | 매일 DB 질의(일시정지 막기) |
| `tests/` | 연습용 시나리오 3개와 추가 경우를 자동으로 시험 |

## 2. 단계
1. **DB 스키마**: 공고 5장 최소 참고안 + `tf_applications`의 학생당 대기 1건 부분 유일 인덱스 + `tf_ai_logs`.
2. **규칙 함수(rules.py)**: `required_coverage`(기획자·웹 프로그래머를 서로 다른 학생으로 채울 수 있는 수),
   `join_block_reason`(정원 → 주 역할 중복 → 필수 역할 자리 순서로 검사).
3. **지원·투표(service.py)**: 모든 쓰기는 `pg_advisory_xact_lock`으로 한 줄로 세움.
   투표가 모두 찬성이면 그때 `join_block_reason`을 다시 불러 승인 직전 검사.
4. **마감**: 설정 `closed=1`, 대기 지원 거절, 1명 팀 해체.
5. **배정**: ① 모든 경우를 따져 규칙을 지키는 배정이 있는지 먼저 확인(없으면 이유를 보여 주고 끝)
   ② 1·2·3차 모델을 차례로 부르고, 답마다 다섯 가지 검사 ③ 모두 실패하면 ①에서 찾은 배정을 씀.
6. **AI 시간 제한**: 요청은 별도 스레드에서 보내고, 화면 쪽에서 1초마다 경과 시간을 재서 120초가 되면 끊음
   (`requests`의 timeout은 응답 시작까지만 재므로 이것만으로는 부족함).
7. **화면**: 학생 화면과 관리자 화면의 팀 목록을 `@st.fragment(run_every=3)`로 감싸 바뀐 부분만 다시 그림.
   단추는 `on_click` 콜백으로 처리해 결과 안내(`result`)가 같은 실행에서 바로 보이게 함.
8. **시험**: `tests/run_scenarios.py`(부록 시나리오), `tests/test_extra.py`(검사·시간 초과·CSV·유일성 제약).
9. **배포**: 비공개 깃허브 저장소 → Streamlit Community Cloud, Secrets 입력, 공개로 바꾸기.

## 3. 3장 표에서 고른 해결
| 기능 | 해결 | 구현 위치 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결(`st.fragment`, 3초) | `student_live`, `admin_live` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결(지원 단계에서 막음) | `rules.join_block_reason` |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결(승인 직전 재검사, 투표가 끝난 순서로 처리) | `service.vote` |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결(DB 유일성 제약) | `schema.sql`의 `tf_members` |
| AI 응답이 늦을 때 | 어려운 해결(모델마다 전체 120초) | `ai.call_model` |
| 3차 모델까지 실패 | 어려운 해결(모든 경우를 따져 배정) | `rules.solve` |
| AI 대기 중 화면 | 어려운 해결(몇 차 모델을 기다리는지 표시) | `do_assign`의 `tick` |
| DB 일시정지 막기 | 어려운 해결(깃허브 액션 매일 질의) | `.github/workflows/db-keepalive.yml` |
